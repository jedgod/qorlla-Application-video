# A3: authority integration and certification (first slice) and review of the supplied `security-v23` overlay

## SCOPE DECISION (owner, after this slice was written): Voice Engine only; no Twilio, no public numbers, no PSTN
The owner confirmed that Twilio is not needed and that the system's own Voice Engine (internet calls between Qorlla accounts, by extension) is the calling function. No in-house carrier or number-issuing service exists in the repository. Consequences:
- **Out of scope / parked, not deleted:** the Twilio adapter, public-number provisioning and release, Numbers & Plans carrier reconciliation, the PSTN authorization gateway, caller-ID-from-inventory, billing holds on numbers. The code and tests stay in the tree (nothing destructive) but are inert: no carrier is configured (`PHONE_CARRIER` unset = `UnconfiguredProvider`), `VOICE_NUMBERS_ENABLED=false`, no workload holds the `pstn.*` scopes in any deployment.
- **Struck from the blockers below:** P0 "Real Twilio reconciliation", the real-data migration rehearsal for number tables, number-lifecycle alerting, number suspension at a carrier, and "calling integration" for public numbers. They return only if a carrier or number provider is ever adopted (then it needs its own adapter behind `TelephonyProvider` and the same certification matrix).
- **Still in force:** Shield workload identity, account verification/suspension, guest rules (meeting ID + passcode only, no extension, no voice, no messaging), tenant isolation, Meet signaling gate, replay protection, fail-closed behaviour, emergency suspension of voice sockets and meeting sessions, TURN/multi-host/failover/device/load/security-review gates.
- Extensions are the only identifiers: engine-assigned, 3-8 digits, never emergency numbers. A verified mobile number remains only an optional discovery attribute (see `VOICE_IDENTITY_AND_DISCOVERY.md`), never a routing key.

Branch `feature/number-authority-a3` (from `integration/shield-main-app-meet`, which includes A1/A2). `VOICE_NUMBERS_ENABLED=false`; production numbers and PSTN are NOT enabled. Release BLOCKED.

## Not done: P0/P1 items that cannot be closed from this repository alone
1. **Real Twilio reconciliation (P0).** Never run against Twilio. The adapter's `numberExists` / `findOwnedByE164` and its error mapping (what a timeout, 404, 5xx or 429 really looks like) are unproven. Certification matrix to run with controlled credentials (extends `cert/provider/run-twilio-cert.mjs`): purchase ok; purchase answer lost (kill the connection after the request is sent) then reconcile finds the number; purchase refused (4xx); release ok; release 404; release timeout after effect; release timeout without effect; carrier 5xx; rate limit 429; reconcile when Twilio is unreachable. Evidence per case: request ids, Twilio SIDs, the resulting `qphone_provider_operations` and `qphone_numbers` rows. Twilio test credentials only accept a few "magic" numbers, so ambiguous-outcome cases need a real (cheap) sub-account or a provider-side fault injector; needs the owner's approval and credentials.
2. **Production workload identity (P0).** Application-layer JWTs only. Needed: trusted issuer, certificate-based service authentication (the supplied overlay's `shield-client.cjs` shows an mTLS client with a mandatory CA and client certificate and an injected token provider: a sound transport shape, not adopted as-is), rotation and revocation tested.
3. **Real-data migration rehearsal (P1).** v4_16/v4_18 were exercised on synthetic data only (including pre-existing duplicate conflicts). Needs sanitized production-like data, rollback and reconciliation rehearsal.
4. **Observability (P1).** No alerts yet for outbox lag, version gaps, unresolved carrier operations or projection conflicts. The data exists (`qphone_number_outbox`, `voice_number_gaps`, `qphone_provider_operations`, `voice_number_projection.conflict/stale/hold`); metrics endpoint and alert rules are not written.
5. **Calling integration (P1).** `voice.js`, the Phone page and the gateways do not yet read authoritative number state; PSTN calling stays disabled.
6. Suspension of an account does not suspend its numbers at the carrier (the engine denies the account regardless). Billing holds do not suspend numbers either.

## Review of the supplied `shield-main-app-meet-integration` folder (`security-v23`)
A full copy of the repository at `4e16f49` plus `security-v23/` and a change to `server.js` `join_room`. Findings:
- **Good and adopted in spirit**: it covers the main app's built-in room `join_room`. Reviewing it exposed a real gap in my wiring, now fixed: suspending an account did not end its live built-in-room sessions, and anonymous/unverified users could create meetings. Both are now enforced and tested.
- **Not adopted as written**: (1) it makes the **Shield** the admission authority for guests (`guest/request`, `claim`, one-time media credential) inside the built-in room, which duplicates the passcode/waiting-room authority that the main app (built-in room) and Meet already have, and its README admits no frontend exists, so enabling it refuses every guest; (2) it **requires `emailVerified` to join** a meeting, which contradicts the agreed rule (guests and unverified accounts may join an existing meeting with ID and passcode under its admission policy; they just get no voice, numbers or messaging); (3) it is based on `4e16f49`, so it lacks number sync, suspension holds, strict-verified engine auth and the Meet signaling gate.
- **Adoptable later**: the mTLS client (`shield-client.cjs`: mandatory CA + client cert, rejects bad TLS, injected short-lived token provider, size/time limits) and `admission.cjs` negative tests, once a real workload issuer exists.
