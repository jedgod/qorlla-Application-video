# Qorlla Voice Engine (v1.0 - v1.11.1): self-hosted internet calls

Qorlla-to-Qorlla voice over the internet, with no Twilio and no carrier account: one-to-one calls and group calls (up to 6 people). It does **not** call ordinary mobile or landline numbers; that needs a separate public-telephone connection (the carrier adapter stays disabled).

**Status: development / pre-production. Release status: BLOCKED.** Version 1.9 does not establish production readiness: that needs the real deployment to pass integration, security, failover and real-audio testing. See [VOICE_CERTIFICATION.md](VOICE_CERTIFICATION.md) for every gate (DR-01..10, QVE-01..15) and exactly what evidence exists. **Voice is off in the main app unless `QORLLA_VOICE_ENABLED=true` and `VOICE_ADMIN_SECRET` are both set**; keep it off in production until the gate passes.

## Architecture
- `qorlla-voice-engine/` is a standalone Node service (express, ws, pg, jose, redis). **PostgreSQL is the source of truth.** Redis is optional and only moves messages between replicas; if it is down, calls on the same node keep working and committed events wait in the outbox.
- A state change and the durable events about it (`incoming`, `state`, `device_revoked`, `device_claimed`, `room_invite`, `room_state`) commit in **one transaction** (`src/store.mjs`, `src/rooms.mjs`, `src/reliability.mjs`). A worker (`src/outbox.mjs`, one per replica) publishes them at least once **and, for one account, in order**: an event is claimable only when no earlier event of the same account is still undelivered, so a claim takes at most the head of each account's queue (`sql/009`, a partial index on the undelivered rows). Browsers apply each event id once and also ignore a call or room state older than the one they hold, so even a duplicate or late delivery cannot overwrite newer state or ring for a finished call.
- SDP and ICE are transient (never stored). A lost signal means the browser renegotiates (ICE restart).
- A reconnecting device sends `resume` with its last event id, receives what it missed (only its own account's events), then reconciles with `GET /calls/live` and `GET /rooms/live`.
- Fencing: every SDP/ICE message carries the sender's **generation**. The engine reads the current lease from PostgreSQL for every message, so every replica decides identically. A device that was replaced gets `device_revoked`, stops its media at once, and cannot signal, renew, or fail the call.
- `src/store.mjs` ties it together with advisory locks per account, so an account is in at most one call or joined room.
- **Outbox failure recovery** (tested in `outbox-order.pg.test.mjs` and end to end through a Redis outage): a failed publish retries with a short capped backoff (250 ms doubling to 5 s) and holds back only that account's later events; a publish that hangs times out (`VOICE_OUTBOX_PUBLISH_TIMEOUT_MS`, 5 s); a Redis outage is retried for as long as it lasts and never counts against an event; an event that fails `VOICE_OUTBOX_MAX_ATTEMPTS` (25) times for its OWN reasons is a poison event: it is set aside (`dead_at`) so it cannot block its account for ever, it stays in the event log and is replayed to a reconnecting device, and it is counted (`qorlla_voice_outbox_dead`, alert `VoiceEventSetAside`) because it means a bug; a worker that dies holding a claim blocks only its accounts until the 30 s lock expires; a failure while marking events delivered is retried, and if it persists the events are delivered again (duplicates are deduplicated by id). The first version of the faster worker claimed batches by event id alone, which let racing replicas deliver one account's events out of order (a reproduction misordered 12 of 12 accounts); that is what this release fixes.
- **Ordering:** every event writer takes a per-account lock before inserting and holds it to COMMIT, so for one account event-id order equals commit order and a replay cursor can never skip an event. Clients also ignore a call/room state older than the one they hold.
- **Group call history** (`sql/007`, `src/history.mjs`): each member's outcome (`ongoing`, `completed`, `declined`, `missed`, `cancelled`, `kicked`; `ringing` while an invitation is open), one participation segment per stay (a person who leaves and rejoins has several; duration is their sum) and a timeline are written in the same transaction as the room change, so the history cannot lag or disagree with the room. A person sees only calls they were invited to or joined; other participants are counted, never named. The Qorlla Group Call History v1 package's API contract, statuses and privacy rules were adopted; its separate event projector and tables were not, because they would duplicate the room tables in the same database and need a reconciliation job for out-of-order events that this design does not have. Pagination uses an exact-microsecond `(created_at, id)` cursor.
- **History retention and privacy** (`sql/008`, `src/history.mjs`): `VOICE_HISTORY_RETENTION_DAYS` (default 365; `0` keeps for ever; valid 7-3650; anything else falls back to 365 with a warning, never to "keep for ever") drives a scheduled cleanup (about hourly, safe on several replicas). Only **ended** rooms are ever deleted, with their members, stays and timeline. A person can delete their own record of one ended call, or of all ended calls (`DELETE /v1/voice/history/:id`, `DELETE /v1/voice/history?confirm=all`, in the page behind a second confirmation with Cancel focused): their stays, timeline entries, member row and already-delivered copies of the room events go; the others' records and the head count they see are unchanged, and what the person did to others stays but anonymously. A call in progress or an open invitation cannot be deleted (409). **Legal hold** (administrators only, `/v1/voice/admin/legal-holds`): a held room is never deleted by retention or by a user (the foreign key makes the database refuse too); a user's deletion request then hides the record from them at once and completes when the hold is released. Deletion and cleanup never touch live rooms, one-to-one calls, device leases, or undelivered events (the outbox): the only event rows removed are the person's own copies that were already delivered. `voice_history_ops` records what the cleanup and deletions did (counts only).
- Group calls are a full mesh: the member who joined later makes the offer to each earlier member. The server relays signaling only; it never carries or records audio.
- Main app: `voice.js` mints the 300 s ES256 token, publishes the JWKS, serves the SDK (`/voice-client.js`), and provisions identities through the admin API (the admin secret never reaches a browser).

## Configuration (engine)
`PORT`, `DATABASE_URL`, `VOICE_JWKS_URL`, `VOICE_JWT_ISSUER`, `VOICE_JWT_AUDIENCE`, `VOICE_ALLOWED_ORIGIN` (exact origins), `VOICE_ADMIN_SECRET` (>= 32 chars, otherwise the admin API answers 503), `VOICE_WS_QUERY_TICKET=off` (keep tickets out of URLs), `VOICE_RING_SECONDS`, `STUN_URL`, `TURN_URLS` + `TURN_SHARED_SECRET`, `VOICE_REQUIRE_TURN`, `VOICE_RELAY_ONLY`, `REDIS_URL`, `VOICE_OUTBOX_MAX_PENDING`, `VOICE_OUTBOX_MAX_AGE_SECONDS`, `VOICE_OUTBOX_INTERVAL_MS`, `VOICE_LEASE_GRACE_SECONDS`, `VOICE_EVENT_RETENTION_HOURS`, `PG_POOL_MAX`, `VOICE_READY_MAX_LAG_SECONDS`, `VOICE_HISTORY_RETENTION_DAYS`, `VOICE_OUTBOX_PUBLISH_TIMEOUT_MS`, `VOICE_OUTBOX_MAX_ATTEMPTS`, `VOICE_API_RATE_PER_MIN`, `VOICE_CALL_RATE_PER_MIN`, `VOICE_ADMIN_RATE_PER_MIN`. See `qorlla-voice-engine/.env.example`. Main app: `QORLLA_VOICE_ENABLED=true`, `VOICE_ADMIN_SECRET` (same value), `VOICE_PORT` or `VOICE_URL`, `VOICE_INTERNAL_URL`. With no secret, Voice is off and the Phone page says so.

Migrations (`sql/001`-`009`, additive and idempotent; `npm run db:migrate`, or `npm run dev:stack` applies them): identities and calls, tickets, devices/leases, reliability (events, outbox, cursors), group rooms, operations (consumer dedupe, certification runs), group history, history retention, outbox ordering.

**Deployment (staging):** `deploy/docker-compose.staging.yml` runs PostgreSQL (the bootstrap creates a migration role that owns the schema and an app role with data access only, `deploy/roles.sql`), Redis with a password, a one-shot migration job and two replicas from one image. The services connect as the app role. Then `node scripts/staging-smoke.mjs http://127.0.0.1:4601 http://127.0.0.1:4602` (it plays the identity provider). Staging only: no TLS, load balancer or coturn.

## Operations runbook (draft: not yet exercised in a drill)
- **Health:** `/healthz` (process); `/readyz` (database; answers `degraded: ["redis"]` when Redis is down but keeps serving, so a node keeps the calls it already holds); `/v1/voice/operational/readiness` (strict: 503 when Redis is configured but down or the oldest undelivered event is older than `VOICE_READY_MAX_LAG_SECONDS`, default 60). Use the strict one to decide where NEW calls may go, the lenient one for restarts.
- **Metrics:** `GET /v1/voice/admin/metrics` (JSON) and `?format=prometheus` (scrapers may send `Authorization: Bearer <admin secret>`; that form works for this one path only). Starting rules: `deploy/alerts.example.yml` (not yet loaded into a live Prometheus).
- **Alert on** (admin secret): `outbox.pending`, `outbox.oldestSeconds` (alert well before the fail-closed limits `VOICE_OUTBOX_MAX_PENDING` / `VOICE_OUTBOX_MAX_AGE_SECONDS`), `outbox.failed`, `sockets.slowClosed`, `bus`.
- **Redis down:** nothing to do for correctness. Events queue in PostgreSQL and drain when Redis returns. Cross-node signaling (SDP/ICE) is lost during the outage; calls renegotiate.
- **Events set aside (`qorlla_voice_outbox_dead` above 0):** an event failed repeatedly for its own reasons. Read `SELECT event_id, attempts, last_error FROM voice_outbox WHERE dead_at IS NOT NULL`, fix the cause, then either leave it (devices get it on their next resume) or clear it with `UPDATE voice_outbox SET dead_at = NULL, attempts = 0, available_at = now() WHERE event_id = ...` to have it delivered live.
- **Overloaded (`503 overloaded`):** new calls/rooms are refused while the backlog is over its limit; existing calls continue. Find why the worker is not draining (Redis, a stuck publisher, database).
- **Rolling restart:** stop a replica (SIGTERM closes sockets with 1001); clients reconnect, resume from their cursor, and reconcile. In-flight events stay in the outbox. Restart one replica at a time.
- **Retention:** delivered events older than `VOICE_EVENT_RETENTION_HOURS` are pruned; undelivered events never are. Keep the window longer than your longest expected client absence. Group call history follows `VOICE_HISTORY_RETENTION_DAYS`. **Legal hold:** `POST /v1/voice/admin/legal-holds {roomId, placedBy, reason}` (admin secret, server-to-server only); release with `DELETE .../legal-holds/:roomId`; a deletion request made during a hold completes on the next cleanup after release. Run the cleanup now with `POST /v1/voice/admin/history/purge`.
- **Redis credentials:** use the least-privilege user in `deploy/redis-acl.example.conf` (publish/subscribe on one channel). A wrong Redis password does not crash the engine: it retries quietly and reports `bus: down` (alert VoiceRedisDown).
- **Secrets:** rotate the signing key by publishing both keys in the JWKS; rotate `TURN_SHARED_SECRET` in coturn and the engine together; the admin secret is server-to-server only. Protect Redis with ACL + TLS: **anyone who can publish to the channel can inject signaling** (envelopes are validated for shape and age, not authenticated).
- **Reverse proxy:** WSS only; do not log query strings; forward `Origin`.
- **Rollback:** the migrations only add tables/columns. To roll the engine back, deploy the previous version: it ignores the new tables. Clients of the previous SDK cannot connect to v1.2+ (the ticket request now needs a device id), so roll the main app's `voice-client.js` back with it. Do not drop `voice_reliable_events`/`voice_outbox` while any replica of the new version runs.

## Verified (and where)
Everything below ran on **one machine**: real PostgreSQL (Docker), a disposable real Redis and coturn (our own containers), headless Chromium with a synthetic microphone.
- Engine: 108 tests (`npm test` in `qorlla-voice-engine/`): atomic state+outbox with a simulated crash before COMMIT, ring timeout and suspension events, replay/ack rules and pagination, duplicate delivery, a dead worker's claim, device takeover and 12 concurrent claims, fail-closed backpressure, stale leases, two replicas with cross-node events/signaling/ownership, forged bus messages, Redis stopped and restarted, a replica killed and replaced mid-call, database connections killed, rooms (invite/join/kick/host transfer/end/expiry/caps/blocks), the SDK against a real engine, ICE policy, event ordering (a deterministic two-writer case and a 40-writer stress with a polling reader), the whole engine running as a least-privilege database role, the release gate, a least-privilege Redis user, history retention/deletion/legal hold (including concurrent deletion and reads, and a randomized 160-step check that the history agrees with the rooms after every operation), group call history (every outcome, rejoin segments, host-transfer timeline, privacy between accounts, pagination with identical timestamps, atomicity, migration backfill, concurrent joins/leaves).
- Browsers (`tests/voice-engine.spec.js`, `tests/voice-reliability.spec.js`, `tests/voice-turn.spec.js`): one-to-one calls with audio both ways over Opus, decline/missed/busy/mic refused/second device ringing; a 3-browser group call with mute, leave and end-for-all; taking a call over on a second device; page reload mid-call; signaling socket drop; ICE restart, including both sides at once; the engine killed and restarted mid-call; a relay-only call through a real coturn.

## Not done / known limits
- **No physical-device test, no calls across different networks, no other browsers** (Firefox, Safari, mobile), no 30-minute soak, no load test.
- **No PostgreSQL primary failover drill**, no measured RTO/RPO, no Redis cluster/Sentinel test, no separate hosts or load balancer.
- **Meet audio integration is not done.** Bridging into Qorlla Meet's media needs a server-side participant on the Meet SFU, which is a separate project. `voice_rooms.meeting_ref` is groundwork only; nothing uses it.
- TURN is tested with a throwaway container, not deployed. Redis authentication/TLS is not configured by this repo.
- Group calls are a mesh (6 people max). Larger rooms need an SFU. **One-to-one call history has no retention or deletion rule yet** (only group history does); decide this in the privacy review. History and audit rows are mutable by the application role (needed for retention and deletion): they are operationally durable, not tamper-proof against a database administrator.
- Load: `scripts/load-test.mjs` exists and was run once on one machine (a relative baseline, not capacity). No staging load, soak or media-plane test.
- Two-node staging was run once in Docker on this machine (image build, roles, authenticated Redis, 15 smoke checks, then torn down). It is wiring evidence, not a staging certification.
- Dev stack: `scripts/dev-stack.mjs` is wired for the engine (migrations, env, `VOICE_REDIS_URL`) but was not restarted in this session; restart it with `npm run dev:stack` to pick the engine up.
- No PSTN, no emergency calling, no billing.
